# Inbox v0.3.1：五项审查修复

2026-10-29。本版在 v0.3.0 正式版本的基础上修复已复现的问题，沿用 `docs/VERSIONING.md` 的增量验收政策。客户界面保持英文，员工接待界面保持中文；没有新增业务接口或数据库迁移。

## 具体修复

| 审查项 | 修复结果 | 回归验证 |
|---|---|---|
| F01：6 个请求耗尽连接池 | 资格读取复用持锁事务的 DB client。 | 6 个并发发送全部完成，只上传一次，连接池继续响应。 |
| F02：来源更正后发送旧关联 | 发送事务先锁定、重读询盘；更正将未发送事件转待核对；已占用发送时拒绝更正。 | 权限查询等待期间更正先提交，旧请求不发送；反方向在途上传时更正被阻止。 |
| F03：新旧通道重复回传 | 新 Test/Live 都检查旧账本；旧自动 Meta Live 队列和 replay 停止发送，保留原记录待核对。 | accepted、dead_letter、已有尝试的 skipped 均不能绕过；Memory/PG 两种 store 均验证旧队列隔离，Mock 继续可用。 |

## 本次验证

本地执行 185 项自动化测试全部通过：Core 117、requirement engine 4、contracts 2、workspace 3、桌面 25、模型 Mock 9、渠道 15、Google guards 10。比 v0.3.0 审查增加 14 项，Core 的数据库测试使用独立 PostgreSQL 16 和虚构记录，未因缺失数据库跳过。类型检查、完整构建、办公室部署包检查、公开文件检查通过；根项目与桌面依赖审计均为 0 条漏洞。

发布复查使用固定版本 Ponytail Audit + Codex 原生分析，然后一次性 Semgrep CE 1.182.0（官方 p/security-audit 快照）和 Gitleaks 8.30.1（源码与全部本地可达历史）。完整命令、规则哈希、命中复核、覆盖缺口和 GitHub CI 回读在随包验证/复查材料中记录。扫描结果和 Mock 测试不等于真实平台受理或匹配验收。

未执行真实 Windows 通知/休眠/升级、资源测量、8 小时观察、真实 Chatwoot/邮件/WhatsApp/CRM/Meta 端到端验收或生产数据迁移演练。现有 Ruby guard 由 GitHub CI 按仓库工作流执行；历史验收不算本版新执行。

## 升级和保留边界

- 服务端修复位于 Core；需要一起更新 Core API 和 worker。仅替换 Windows ZIP 不会应用这些修复。
- 升级前让旧进程的在途外部调用结束，再切换 API/worker，不能让旧发送逻辑继续运行。保留数据库、配置、密钥、附件与全部回执。
- 从 v0.3.0 升级没有新 SQL；更早版本必须具有截至 `009_meta_legacy_receipts.sql` 的既有 schema。兼容文件的数据库要求指完整安装基线，不能当成又新增了一次迁移。
- 旧 Meta Live pending/retrying 进入 review，dead_letter 禁止直接 replay。不要删除账本或清零尝试次数；需先核对是否已经受理，再做专门的历史回执迁移。外部 OKKI 网关不由本次发布自动关闭。
- 来源更正后冻结的未发载荷保留待核对，不自动改绑新访客重发。已经发送或结果未知的回执继续保留。
- 广告默认 Mock；发布不启用 Meta Test/Live，也不对生产服务执行部署。
- 保留历史 tag 与资产。本版客户端仍为未签名 Windows x64 ZIP，使用手动更换目录方式升级，客户端数据目录和渠道绑定不重置。

回退代码不能恢复已发事件的状态；保留 v0.3.0 源码不代表可以直接重开旧 Meta 自动队列。需要回退时仍须隔离旧 Live 发送路径、核对在途回执。
