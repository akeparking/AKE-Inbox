# AKE Inbox v0.3.0 整体源码与发布报告

发布日期：2026-10-28。版本性质：接待与 Meta 回传预发布版。

## 本版解决的问题

先前的办公室运行包没有加载独立开发的 Meta 回传代码。接待导航与询盘来源信息也分散在不同入口。本版整合桌面／办公室分支的修复和 Meta 分支，并在原生会话系统上提供 OKKI Marketing 风格的导航与客户上下文。页面读取真实账号授权范围内的数据；没有关联询盘时明确显示空状态。

## SOP 与官方依据

以用户提供的 Meta Ads SOP 为基础，并在发布当日复核 [Meta CRM Payload Specification](https://developers.facebook.com/documentation/ads-commerce/conversions-api/conversion-leads-integration/payload-specification)。原生表单使用真实 `lead_id`、`system_generated` 和 CRM 来源；网站 Lead 使用其来源页面及原始浏览器信息。联系方式按要求规范化后哈希，源记录与事件标识分开。超过允许时间的事件不能通过修改时间补传。

传输、同意、阶段顺序、前序回执和重复发送规则见 [Meta 回传说明](META_ADS_FEEDBACK.md)。正式开通前仍需要账号凭据、数据集、网站采集／同意安装核验、旧发送方及历史账本对账和实际平台验收；本版未执行 Test Events 或 Live 上传。

## 部署与升级

办公室 WSL 是唯一业务数据写入端。VPS 继续作为公网转发入口并保存此版本的源码和报告备份，不启动旧业务数据库或旧的接待服务。原有网站服务保留。

升级前保存数据库一致性转储及私有配置，保留上一运行包。先执行幂等迁移，再切换版本目录并仅重建应用容器。新增 `008_meta_feedback.sql`、`009_meta_legacy_receipts.sql` 接在已有 `007_office_reception.sql` 之后；不重置用户、渠道、会话或历史数据。Core 健康接口返回实际包版本。

界面需要 Core 的 `MARKETING_ENABLED`、`ATTRIBUTION_UI_ENABLED` 和原生端的 `AKE_MARKETING_ENABLED`、`AKE_MARKETING_UI_ENABLED`。人工资格确认由 `QUALIFIED_FEEDBACK_ENABLED` 控制。部署将 `META_FEEDBACK_ENABLED=true`、`META_FEEDBACK_MODE=mock`，保持 `ADS_MODE=mock` 和 OKKI 写入／同步关闭。网站访问采集仍需单独启用、安装并验证同意流程。

回退时切回旧运行包及对应配置，保留新建表和上线后新增记录。禁止用旧数据库覆盖当前数据库。Windows 用户数据无须迁移，接待协议仍为 2。

## 本次验证

- 独立 PostgreSQL 回归：基础 Core 88 项通过，另行补跑 Meta 专项 23 项通过（其中 8 项与基础运行重叠，补齐 15 项数据库测试）；Core 共 103 项覆盖。需求引擎 4 项、共享契约 2 项、Web 3 项通过。
- 桌面逻辑 25 项、渠道 15 项、Google 保护 10 项、模型适配 9 项、Ruby 归档／邮件／发送保护 17 项通过。
- 原生 Chatwoot 使用独立数据库和虚构客户。验证中文后台、接待开关、400/390/320px 英文客户表单、失败重试、重复提交键、真实隔离收件及 iframe 关闭；浏览器运行时错误为零。
- 新接待／营销 UI 验证客户侧栏、原生资料入口、6 个营销页签、Mock 提示及 1440/1024/390/320px 布局。
- 类型检查、生产构建、办公室运行包、Windows x64 打包、依赖审计及公开源码／密钥扫描按发布流程执行；结果摘要随版本交付。
- 测试在隔离环境进行，未发广告事件、未写 OKKI、未发真实邮件／WhatsApp。Meta 数据库测试因本机磁盘同步延迟首次超时，改用独立测试库的非同步刷盘设置后通过；不声称做过断电耐久性测试，生产数据库设置未变。
- Windows 实机资源、通知和连续 8 小时运行未在本版执行，因此发布为预发布版。

线上与 GitHub 最终回读结果记录在随 Release 交付的 `verification.json`，私有部署路径和数据库转储留在授权本机备份中。
