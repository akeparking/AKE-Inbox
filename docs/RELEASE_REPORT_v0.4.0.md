# AKE Inbox v0.4.0：REA Inbox＋CRM 多租户版本

发布日期：2026-10-29。版本性质：Web／服务端预发布。

本版在已经部署的 v0.3.0 上整合 REA 研究形成的自有 CRM。保留既有接待、Meta 防重放及代理修复，新业务可以记录客户、联系人、独立项目、跟进、报价版本和成交事实。创建商机与人工确认有效为独立操作。

## 使用入口

办公室和公网沿用现有 `/sales` 路由。新工作台为 `/sales/saas`，原生接待台可通过 `AKE_CRM_WORKSPACE_URL` 显示“CRM 工作台”。组织管理员以组织标识和个人 Chatwoot 账号登录，再通过邀请管理成员。

SaaS 使用独立业务数据库、非所有者运行角色和强制行级权限。一个 workspace 对应一个 Chatwoot Account；成员、配置、密钥、广告账户、AI 知识及任务按租户隔离。浏览器不能通过自报身份切换租户。

## 本版能力

| 范围 | 行为 |
|---|---|
| 客户与项目 | 公司多联系人、同客户多个独立项目、负责人、搜索与编辑 |
| 跟进与成交 | 任务、备注、阶段历史、报价追加版本、赢单／输单／重开；修正保留审计 |
| 营销 | Meta／Google 官方读数适配器、日指标、原币种／时区、缺失值、补采和恢复 |
| 报表 | 平台转化、持久询盘、人工有效、商机及赢单分开；首次与末次非直接归因 |
| 回传 | Qualified 与 Won 事件、先保存发送意图、重复保护、未知结果待核对；不因业务修正重发旧事件 |
| AI | 摘要、字段建议、翻译和草稿独立保存，读取当前组织已批准知识 |
| 接待 | 复用原生会话、渠道、附件与人工接管；保留邮件退信保护 |

六个销售阶段可改名。任意多管道、报价 PDF、财务收入确认、历史迁移和自动扣款仍为后续范围。广告授权、站点接线及真实平台匹配需要分别验证，不能用本地 Mock 代替。

## 部署结构

办公室 WSL 是业务写入端。VPS 保留 HTTPS 代理和独立验收环境，旧 VPS 业务库不承担新流量。`deploy/saas/compose.office.yaml` 可使用已经验证并记录摘要的 Node 24 运行镜像及预构建运行包，在镜像仓库不可用时部署。

旧接待与 SaaS Web 使用同一份以 `/sales` 为 basePath 构建的静态资源。办公室 gateway 只把 `/sales/saas`、`/sales/api/saas/` 和 `/sales/api/saas-hooks/` 发往新工作台，其他接待路径保持既有归属。SaaS 数据库不暴露宿主端口。

`/sales/api/saas-hooks/` 只转发受支持的签名收件与平台 Webhook，保留原始正文，并过滤浏览器身份头。实际的租户校验、HMAC、回查消息和幂等处理由 Core 执行。上游不可用返回 503，不伪造收件成功。

## 迁移、切换和回滚

v0.3.0 的 `007_office_reception.sql`、`008_meta_feedback.sql`、`009_meta_legacy_receipts.sql` 保留，SaaS schema 为 `010_saas_crm.sql`。迁移账本以完整文件名与校验和登记，重复运行不重放。未发布开发分支的同内容旧编号不再重复打包。

升级前保存一致性数据库转储、私有配置及旧运行目录；先在恢复副本上执行迁移并比较原有表的记录数量。正式升级不重置账号、渠道、会话、加密密钥或数据库。

租户启用时间与原项目归属共同决定新业务切换；旧项目的新回复继续留在旧业务流程。新业务不向 OKKI 双写。回滚时关闭新入口和出站任务、切回兼容的运行目录，保留新数据与审计；不能用旧数据库覆盖升级后的业务。

## 验证与边界

发布验证包含独立 PostgreSQL 双租户验收、核心与渠道回归、浏览器销售流程、签名入口、路由失效恢复、正式库副本迁移、VPS 隔离测试、源代码／Git 历史扫描，以及发布后的 HTTPS 与版本回读。每项实际结果记录在 Release 附件 `verification.json`。

测试租户、模拟平台回执、真实授权平台受理及平台匹配分别记录。真实 Meta／Google 回传、外部公司业务试点、重新绑定邮件／WhatsApp、Windows 新版长时运行不因本版发布而自动标记通过。完整源码包含桌面客户端，现有协议 2 客户端可继续访问服务端。
