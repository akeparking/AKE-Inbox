# AKE Inbox v0.2.2 · 审查修复预发布版

按办公室多人接待场景修复本轮架构审查中的 5 项问题。用户选择先发布预发布版；本版 Windows 实机验收、资源对比与连续 8 小时观察尚未执行，不能沿用 v0.2.1 的历史验收结果。APP 的正式更新检查不会推荐预发布版，需手动下载。

## 修复内容

- **发送状态与故障恢复（R1-01）**：Core 准入检查在调用渠道前不可用时，异常交给原生任务重试；人工接管或规则明确禁止发送时，消息显示失败。最终邮件拦截器抛出异常，避免未发送邮件被记录为已发送。邮件最后一道检查失败由原生邮件服务显示失败，需核对后人工重试；渠道结果不确定时没有新增自动重发逻辑。
- **权限撤销（R1-02）**：普通坐席需要同时满足当前收件箱成员资格和会话归属，才能读取详情、消息、联系人子资源或接收广播。撤销成员资格后，即使旧负责人字段尚未清理，访问也立即失效；保留管理员和访客的原有权限。
- **多人登录（R1-03）**：成功登录不再消耗整个办公室共用代理 IP 的限额。错误登录按规范化账号计数，使用现有数据库跨 Core 进程共享；每 60 秒最多 8 次失败，成功后清零。账号标识以 HMAC 保存，认证服务故障不计作密码错误。
- **登录保持（R1-04）**：原生页面刷新 token 时保留 cookie 到期时间，已过期 token 不会被延长，异常到期值不能注入 cookie 属性。
- **脚本同步（R1-05）**：采集及同意脚本以 `deploy/marketing` 为唯一维护源，构建同步 WordPress 安装副本，发布检查拒绝不一致版本。

## 本次验证

- 三个独立 PostgreSQL 测试库：根测试 88 项通过，含跨实例并发登录、重复事件、人工接管、取消旧任务和不确定结果处理。
- 桌面离线测试 25 项、模型适配器 Mock 测试 9 项、渠道保护测试 15 项、Google 离线保护测试 10 项通过。
- Ruby 保护测试 17 项通过；固定 Chatwoot 镜像及一次性数据库验证了撤权后的 HTTP、查询和广播限制，以及多人分单和离线收件。
- 类型检查、`/sales` 工作台构建、办公室运行包、Windows x64 打包及发布文件检查见随包 `index.html` 的本次记录。
- 安全扫描沿用本轮固定规则和工具，扫描覆盖限制及复核结论见 `v0.2.2-validation.json`。扫描结果不代表线上安全验收。

## 安装范围与未完成项

本次发布源码、Windows x64 ZIP、办公室运行包、离线说明和 SHA-256 校验清单。发布到 GitHub **没有更新正在运行的办公室/VPS 服务**。发送、权限、登录和 cookie 修复位于服务端或服务端提供的页面；仅替换 Windows ZIP 不会应用这些修复。管理员部署前应保留现有配置及备份，并同步更新 Core、工作台与 Chatwoot 定制文件。
