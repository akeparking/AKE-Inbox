02 / 同事只需三步

  1. 下载 Windows ZIP本版为接待与 Meta 回传正式版，可从 v0.4.0 Release 下载，或通过 APP 的正式版本更新检查发现。仅有 source 的 v0.2.0 是源码预览，不能当作 EXE 使用。
  2. 完整解压，然后打开 EXE不要只拖出单个 EXE，也不要在压缩包预览窗口内运行。系统要求 Windows x64；首版未做代码签名。
  3. 登录自己的接待账号公司入口已预置。登录且连接成功后自动接待；管理员可在设置中修改入口。

开机启动默认关闭；提示音默认关闭。登录状态保存在当前 Windows 用户的数据目录中。

05 / 更新一个 ZIP，保留原来的工作

  1. 检查更新APP 每天自动检查最多一次；也可在设置中手动检查。GitHub 暂时不可达不会停止接待。
  2. 下载并核对版本只推荐带 Windows 包与 SHA256SUMS.txt 的正式 Release。校验 ZIP 的 SHA-256 应与清单一致。
  3. 退出旧版，解压新版到新目录先通过托盘菜单退出，避免覆盖正在运行的文件。无需重新迁移数据库或清空渠道绑定。
  4. 打开新版，检查接待状态沿用相同 Windows 用户的数据目录，地址、设置和有效登录保持。若账号会话自然过期，重新登录即可。

回退方式

退出新版，再打开保留的旧版目录。旧客户端可以连接本版兼容后台，但旧客户端没有按实例租约和新版提醒能力。

07 / 运行边界与日常维护

API Key 与业务数据放在哪里？

公司 Key 只在办公室主机的受限服务配置中。数据库、附件和渠道登录也由主机管理。Windows 包、源码包、HTML、GitHub Release 和 VPS 中转均不包含 Key。客户端缓存上限 64 MiB；应用不写持续增长的自有业务日志。

关闭通知后会漏掉工作吗？

系统通知或勿扰模式可能阻止横幅。任务栏闪动、托盘数字及工作台未读仍保留。声音与系统通知可在设置中单独控制；请以工作台未读为准。

为什么首版不自动覆盖升级？

首版使用提示更新和手动 ZIP 升级，以保留可回退目录。当前为未签名 Windows x64 包；签名、静默升级和 ARM 原生版本不在本版范围。

要重新绑定渠道账号吗？

本次升级不清空绑定或重新迁移数据库。审查修复需同时更新办公室 Core 与 Chatwoot 定制；仅更换 Windows ZIP 不会应用服务端修复。只有渠道自身登录过期、已解绑或连接失败时，管理员才需要重新绑定；以主机渠道状态为准。

办公室主机如何保持可用？

使用已配置的常驻服务，确保主机供电、网络和 WSL 服务正常，并避免自动睡眠。关闭同事电脑不会停止主机 AI。现有邮件退信循环防护继续保留，本版不添加新的邮件提醒链路。
