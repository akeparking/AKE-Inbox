# AKE Inbox v0.4.3：真实平台接入与部署

在 v0.4.2 审查修复和多租户 CRM 基础上，连接获授权的 Meta、Google Data Manager 与真实 AI。WSL 办公室已升级 Core、SaaS API、worker 和工作台；VPS 已切换同版运行包与公网中转，WSL 仍是唯一业务写入端。原接待渠道、切换时间、邮件退信保护、附件归档与人工接管保留。

## 实际结果

| 能力 | 本次验证 | 保留的边界 |
|---|---|---|
| Meta 广告读数 | 官方 API 同步最近 30 天，返回 22 条日/广告系列记录；重复同步没有重复行 | 保留账户币种、时区与缺失值；平台转化不等于有效询盘 |

| Google Ads | 官方读取适配器和刷新逻辑已实现 | 新增 Ads 授权被 Google 本人验证步骤阻止；按用户决定保留待验收，未创建通行密钥或更改账号安全设置 |
| AI | 真实摘要、字段建议、翻译、草稿及浏览器流程通过；生产运行环境再次调用成功 | 使用虚构验收内容，未向客户发送消息；建议不覆盖人工字段，实际返回模型单独保存 |

AI 支持 Anthropic 与 OpenAI 兼容协议，限制服务器允许的 HTTPS 来源，拒绝重定向、截断输出及工具调用。实际调用记录区分所请求的模型别名和服务返回模型。

Meta CRM 阶段反馈区分原生表单与网站询盘来源，只有真实平台线索编号才进入原生表单语义。沿用 v0.4.2 的并发锁、旧账本防重及未知回执待核对规则。没有为了验收而制造客户询盘、广告转化或用户同意。

## 升级与回滚

1. 保存数据库、加密密钥、私密配置、原服务定义和旧运行目录。不要清空回执、发送意图或现有业务。
2. 使用 Node 24 构建，执行新增 `011_live_integrations.sql`。SaaS 数据库随后执行 `finish-schema.cjs` 安装行级权限和运行角色授权；不可在原办公室业务库安装 SaaS 行级权限。
3. 一起更新 Core、SaaS API 与 worker，切换工作台及 VPS 中转。原生文件内容未变时可以保留渠道进程。
4. 按租户配置官方账户、原生表单轮询及模型。Google Data Manager 默认仅验证，Google Ads 与赢单目标分别配置和验收。私密部署可以设置企业出站代理，凭据不随源码分发。
5. 核对同步、任务、身份、旧入口和平台回执。回退先停新出站任务并切回兼容运行目录，保留新产生的数据与审计，不用旧备份覆盖现有业务。

本轮没有新执行 Windows 实机长时运行、外部公司试点、真实新询盘到广告平台匹配的全链路验收。它们保持待验收，不计为本次通过项。采购、库存、财务、历史 OKKI 迁移和自动调预算不在本版范围。
